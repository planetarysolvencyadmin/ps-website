# Images: how they work and how to maintain them

The home page uses a full-width hero image (chosen at random from a pool) and five circular section links. The same section pictures also appear in the round header of each section page. All of them come from one image library, so pictures can be added, swapped or retired without touching any templates.

## How it fits together

| Piece | Where | Edited by |
|---|---|---|
| Full-size originals | Outside the repo (your own folder, never committed) | You |
| Resized files (WebP and JPEG) | `assets/images/library/` | Generated by the script, do not edit |
| Descriptions: alt text, credit, licence, crop point | `_data/images.yml` | You |
| Which sizes exist for each image | `_data/image_files.yml` | Generated by the script, do not edit |
| Which images the hero chooses from | `_data/hero_images.yml` | You |
| The hero headline, and whether to pin one fixed image | Front matter in `index.md` (`hero_title`, `hero_image`) | You |
| Which image each section circle and section page header uses | `_data/home_sections.yml` | You |
| Section circle labels | `_data/navigation.yml` (same `url`) | You |

Every image has an **id**: its filename without the extension, lower case and hyphenated, for example `cloud2` or `fossilfuels2`. The id is what you type in `index.md` and `home_sections.yml`, and it is the key in `images.yml`.

## The orbit treatment

Every image the script writes carries the brand "orbit" treatment, recreated from the design agency's artwork at web resolution:

- a frosted circular **lens** in the centre (a blurred copy of the photo, slightly lifted) with a white ring;
- two thin white **orbit** lines crossing it, one solid and one dashed, tilted in opposite directions;
- no logo in the lens.

Section pictures get a smaller lens (50% of the picture rather than 81%) because they are shown in small circles. On the home page hero, the band crops the top and bottom of the picture, so the lens and orbits are partly cut off; that is expected.

Everything is measured as a fraction of the picture, so it scales to every size. To tune it (lens size, blur, line weights, orbit shapes and tilt), edit the `TREATMENT` block at the top of `scripts/process-images.mjs` and run the script again. It notices that the settings changed and rebuilds everything, which takes a few minutes for the full library.

Use `--no-treatment` to produce plain resized images for local comparison only. **Do not commit plain images.** Only treated pictures should be published unless the untreated picture is licensed.

## What the script produces

`scripts/process-images.mjs` reads each original and writes, to `assets/images/library/`:

| Use | Files | Notes |
|---|---|---|
| Hero | `<id>-2400`, `-1600`, `-800` | Full image, not cropped. Resized to that width. |
| Section circle | `<id>-sq-600`, `-sq-300` | Centre-cropped to a square. |

Each size is made as WebP (quality 78) with a JPEG (quality 80) fallback, with the treatment applied. Browsers pick the smallest suitable size through `srcset`, so a phone downloads the 800px hero and a large screen the 1600px or 2400px one.

It also:
- strips all metadata, including GPS and camera details;
- converts to sRGB;
- never upscales. If an original is narrower than a target size, that size is skipped, and an original smaller than every size is kept at its own width;
- skips files that are already up to date, so it is safe to re-run. It records the settings it used in `assets/images/library/.process-settings.json` and rebuilds automatically if sizes, quality or treatment change.

Every original produces both hero and square versions. Use `--only hero` or `--only section` to limit this.

## Adding new images

1. **Install the tools once.** You need [Node](https://nodejs.org) and [ImageMagick](https://imagemagick.org) with WebP support. On Windows, `winget install ImageMagick.ImageMagick` works. Open a new terminal afterwards.
2. **Name the original sensibly.** The filename becomes the id, for example `flood5.jpg` gives `flood5`. Use `.jpg`, `.jpeg`, `.png`, `.tif`, `.tiff` or `.webp`. Two files that become the same id (for example `Flood 5.jpg` and `flood-5.png`) stop the script with a message.
3. **Put it in the originals folder.** The default is set at the top of the script. Use another folder by passing it as an argument or by setting `PS_ORIGINALS`. If you choose a folder inside the repo, add it to `.gitignore` first: the script refuses to run otherwise. `/originals/` is already ignored.
4. **Run it from the repo root:**
   ```
   node scripts/process-images.mjs
   node scripts/process-images.mjs "D:\other\folder"
   ```
5. **Add the description.** The script prints a stub for each new image. Paste it into `_data/images.yml` and fill it in (see below).
6. **Commit** the new files in `assets/images/library/`, plus `_data/image_files.yml` and `_data/images.yml`. Check the Cloudflare preview before merging.

Use `--force` to rebuild everything regardless. Processing is slow (the blur is heavy at 2400px): allow a few minutes for a full library.

### Choosing good originals

- **Hero:** landscape, at least 2400px wide, with interesting detail across the whole frame. On a wide desktop screen the hero is cropped to a band about twice as wide as it is tall, so a 3:2 photo loses a slice from the top and bottom. On phones it is cropped more tightly. Keep the main subject near the middle.
- **Section circles:** the centre of the picture is what shows, and the lens covers the middle. If the subject is off-centre, crop the original first, because the script crops to the centre.
- **The lens hides the middle of the picture,** so pictures whose interest is at the edges work better than ones with a single subject dead centre.
- Keep source images under about 15 MB. Very large originals are fine but slow to process.

## Describing an image (`_data/images.yml`)

```yaml
cloud2:
  alt: A rotating supercell storm over open farmland and a straight road, with rain falling beneath the cloud base
  credit: Photographer or source name
  licence: e.g. Licensed from Example Stock, or CC BY 4.0
  focal: "50% 65%"
```

- **`alt`** is read by screen readers when the image is the hero. Describe what is in the picture, briefly and concretely, without starting "Image of". The section circles ignore it on purpose (the visible label already names the link), so they are not read twice.
- **`credit`** and **`licence`** are kept for the record and are not shown on the site yet. Keep them accurate; they are the evidence that you may use the picture.
- **`focal`** is optional and only affects the hero. It is a CSS `object-position` such as `"50% 30%"`: the first number is how far across (0% left, 100% right), the second how far down. Raise the second number to keep more of the lower part of the picture when the hero is cropped.
- Ids are lower case with hyphens, no spaces. The key must match the filename id exactly.

Entries marked `TO CONFIRM` need a real credit and licence before launch.

## Changing the hero

### The random pool

Each visit to the home page shows one image picked at random from `_data/hero_images.yml`:

```yaml
- flood1
- fire2
- drought1
```

- Each line is an image id from `images.yml`. Add a line to include an image, delete or comment it out (`# - cloud1`) to exclude it. The file also lists the images that are available but currently left out.
- The choice is made in the visitor's browser, so it changes on every visit and only the chosen image is downloaded. If JavaScript is off, the page shows one image from the pool picked when the site was built.
- Ids that are not in `images.yml` are skipped, so a typo cannot break the page.
- Dark images (the cloud ones, for example) are left out by default: the headline is still readable on them, but the picture itself ends up looking heavy.

### Pinning one image

In `index.md`:

```yaml
hero_image: random
hero_title: Managing planetary risk. Protecting human prosperity.
```

Set `hero_image` to an id such as `fire2` to show that image every time, or back to `random` to use the pool. `hero_title` is the page's `<h1>`.

The hero is loaded straight away (never lazy-loaded) because it is the first thing visitors see.

### Legibility is automatic

A dark navy panel sits behind the headline and fades out above it. White text on that panel over a pure white photo still measures about 6.5:1, so it passes WCAG AA (4.5:1) whatever picture you choose. A very bright image will look a little darker around the text than a dark one; that is intended. If an image has a distracting feature in the dark panel area (a bright sun, say), use `focal` to move the crop.

## Changing the section circles and page headers

Edit `_data/home_sections.yml`:

```yaml
- url: /explore/
  image: coral2
```

- Change `image` to any id in `images.yml`.
- The label under each circle comes from the menu in `_data/navigation.yml`, matched by `url`. Rename the menu item and the label follows.
- The same image is used in the round header at the top of that section's own page, so the circle and its page always match. (Other pages can still set `image:` in their front matter, with `image_alt` left blank.)
- Order of the list is the order on the page. To add or remove a section, add or remove an entry here and make sure the menu has a matching `url`.

### Circles to squares

Add the `section-links--square` class to the `<nav>` in `_includes/section-links.html`:

```html
<nav class="section-links section-links--square" aria-label="Sections">
```

The corner radius is the `--tile-radius` variable in `assets/css/style.css` (50% is a circle, `12px` a rounded square). The coral ring follows whichever shape is set.

## Retiring or replacing an image

- **Retire from the hero only** by taking its line out of `hero_images.yml`.
- **Replace** by putting a new original with the same filename in the originals folder and running the script with `--force` (the script only reprocesses originals that are newer than their outputs, so `--force` is the safest option for a replacement).
- **Retire** by deleting its files from `assets/images/library/` (every file starting with `<id>-`), removing its entry from `images.yml`, then running the script once so `image_files.yml` is rebuilt. First make sure no front matter, `hero_images.yml` or `home_sections.yml` entry still uses it.

## Using library images elsewhere

Other templates can use the same machinery through `_includes/responsive-image.html`:

```liquid
{% include responsive-image.html id="ocean1" kind="hero" sizes="100vw" class="my-class" %}
```

- `kind` is `hero` (wide) or `square`.
- `sizes` tells the browser how wide the image will display, so it can choose a file. For example `(min-width: 900px) 50vw, 100vw`.
- Add `priority=true` only for a large image at the top of the page (it then loads early); `eager=true` for a small image that is visible straight away. Otherwise it is lazy-loaded.
- Add `decorative=true` for `alt=""` when a visible label already describes it.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| The hero or a circle is missing entirely | The id in `index.md` or `home_sections.yml` has a typo (for the random hero, a pool that is empty or all typos), or is not in both `images.yml` and `image_files.yml`. The template outputs nothing rather than a broken image. |
| The script says ImageMagick was not found | Install it and open a new terminal. On Windows the script uses `magick`, not the system `convert`. |
| The script says the originals folder was not found | Pass the folder as an argument or set `PS_ORIGINALS`. |
| The script says the folder is inside the repo but not ignored | Add the folder to `.gitignore` before running. This stops full-size originals being committed. |
| A new image has no description | Run the script again and copy the stub it prints into `images.yml`. |
| The treatment looks wrong or too strong | Adjust the `TREATMENT` block in the script and re-run. |
| A hero looks soft | The original was narrower than 2400px, so only smaller sizes exist. Use a larger original. |
| Alt text or crop looks wrong | Edit `images.yml`; no need to re-run the script. |
| Builds slow down or the repo grows quickly | Each image is about 1.7 MB across all sizes. The JPEG 2400px and 1600px files are only fallbacks for very old browsers and could be dropped from the script if size matters. |

## Rules of thumb

- Never edit files in `assets/images/library/` or `_data/image_files.yml` by hand: the script overwrites them.
- Never commit full-size originals, and never commit untreated (`--no-treatment`) output.
- Every image needs `alt`, `credit` and `licence` before it goes live.
- Check the Cloudflare preview on a phone after changing the hero or circles.
